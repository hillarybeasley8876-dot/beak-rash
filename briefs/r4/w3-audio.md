# r4 job w3-audio — sounds for the r4 mechanics, two new race songs, weather ambience, voice lines (audio unit)

Read SPEC.md §6 (audio), §14–§21 (the r4 mechanics) and §22. All events exist in `src/core/events-map.ts`.
Read `src/audio/` first: `events-race.ts` / `events-combat.ts` (bus → sound, the `Host` helpers `h.play(id, riderId | pos, opts)`,
`h.stinger`, `h.announce`, `h.cooldown`), `sfx/bank.ts` (the `SFX` registry, PREWARM lists) + `sfx/kit.ts` (the
synthesis kit), `music/songs/*.ts` (the song format; `coast.ts` is the reference), `music/stingers.ts`, `voice/` (clips +
barks: a bubble's text → its clip via `idFor(text)`), `debug.ts` (`__br.audio.state() / trace()`), `tools/audio-check.mjs`.

## Build it
1. **A sound for every r4 event** (new file(s), e.g. `src/audio/events-r4.ts` + `src/audio/sfx/r4.ts`; wire from `index.ts`):
   - `police:windup` → a clear rising wind-up tell (it is the player's cue to parry — audible over the music, 0.45 s);
     `police:swing` → baton whoosh; `npc:hit` → the weapon's hit sound (+ a hurt grunt on the player);
     `police:wanted` → a siren chirp per new ★ (★3 = a short alarm stinger); `police:roadblock` → radio blip + sawhorse
     clatter; `police:down` → cartoon bonk + slide whistle down + bike clatter; `police:bribe` accepted → cash register
     "ka-ching", refused → a buzzer; `police:hurt` → a hit.
   - `combat:parry` → a big metallic CLANG ("当！", ringing, `impact: true`), id containing `parry`; `combat:throw` → a
     throw whoosh (pitch per weapon; the slipper flaps).
   - `rider:trick` start → a whoosh up; land → a chime that climbs with `count`; fail → nothing new (the crash sounds).
   - `style:chain` → a soft tick that rises with the chain (rate-limited); `style:bank` → an arpeggio / register, bigger for
     big totals; `broken` → a deflating "wah-wah".
   - `race:nemesis` → a dramatic two-note sting; `race:nemesisDown` → a triumphant one; `race:alliance` form → an ominous
     brass sting, break → a record scratch.
   - `race:event` warn → a PA "ding-dong" chime; start → per kind (fishSpill: truck skid + crash + fish flops; geese: a
     honk chorus; roadworks: a jackhammer burst; stalls: vendor chatter).
   - `secret:found` → a magic chime; ids starting with `duck_` also quack (an id containing `quack` or `duck`).
   Positional sounds use the event's `pos`. Rate-limit anything that can repeat. Add the frequent ones to PREWARM_RACE.
2. **Two new race songs** in the existing format, registered in `songs/index.ts` as `race-watertown` and `race-gobi`
   (the conductor plays `race-<trackId>`), each a full 64-bar loop with sections, fills and the final-stretch layer like
   the others: **watertown** — Jiangnan water town, ~104 bpm, major pentatonic, light swing, a plucked zheng-like hook
   and a sliding erhu-like line over a laid-back funk groove; **gobi** — desert rock-funk, ~132 bpm, phrygian dominant,
   driving toms + handclaps, a bending lead. Use the existing instruments; you may add ONE new instrument (e.g. a
   Karplus-Strong pluck) if `audio-check --offline` keeps its cpu numbers.
3. **Weather ambience**: a rain loop (soft noise bed + droplets) when `session.track.weather === 'rain'`, a wind loop for
   snow and fog (and the gobi always gets a light desert wind); faded in/out with the race, muffled in tunnels/pause
   like the other loops, nothing outside races.
4. **Voice lines** (do this LAST — the line files are still being written by other jobs; read them fresh):
   - fix `tools/gen-tts.mjs` on Windows (`new URL(import.meta.url).pathname` → `fileURLToPath(import.meta.url)`);
   - add LINES for the corgi's lines (`src/data/police-lines.ts`, speaker `corgi`), the nemesis / alliance lines
     (`src/data/rival-lines.ts`, the rider's own speaker), the event announcements (`src/data/event-lines.ts`,
     `announcer`) and the egg lines that are spoken (`src/data/secret-lines.ts`: goose poem → `goose`, sloth → `sloth`);
     `text` must equal the on-screen line exactly so `idFor(text)` finds it; generate with `--only <new ids>` (the API
     works from this machine); the manifest `src/data/voice.ts` is regenerated by the tool;
   - make sure those lines actually play: the corgi's `npc:say` bubbles and the event warn lines go through the voice
     player (announcer channel for the events), the rivals' through the barks as today.
5. On Windows `os.loadavg()` is always `[0,0,0]`, so `tools/audio-check.mjs` never sees a loaded machine: measure the
   load instead (sample `os.cpus()` busy time over ~1 s; > 70 % busy = loaded) and use it the same way (cpu overruns on
   a loaded machine are warnings). Same rule in `audio-check-cpu.mjs`. Do NOT loosen any threshold.
